# TTS 性能与后端比较

适用于学术录播配音过慢、需要选择执行方式或估算整片制作时间的任务。关键词：CPU、核显、Vulkan、预填充、参考编码缓存、量化、生成耗时。具体设备、路径和历史测量保存在本地 `state/` 案例，不把某次结果设为默认性能。

## 先找实际可用的执行路径

使用本地或可管理的远程推理时，查看系统设备清单和后端枚举，区分设备存在、驱动可用、程序编译支持和实际选择的后端。缺少 `nvidia-smi` 不能证明没有 GPU；AMD/Intel 设备还可检查 Vulkan，Apple 设备可检查 Metal。记录运行日志中的实际设备和 CPU 回退，不把“指定了 GPU”当作已在 GPU 上计算。使用托管服务时，以请求、排队、传输和生成的实测耗时为依据，不要求获得服务端硬件细节。

依据可见日志区分耗时阶段；能观察推理过程时，可分别查看模型加载与量化、参考录音编码、预填充、逐帧生成及声码器解码。CPU 推理较慢不一定是纯算力不足，内存带宽、换页、资源限制和其他任务争用也可能有影响；总 CPU 使用率和 swap 占用量不能单独证明瓶颈。日志中的阶段计时可能重叠，不能直接相加。

先测试不改变研究内容和声音目标的方案。能控制计算资源时，可错开密集任务、比较线程数与优先级、复用参考编码，再检查后端或硬件加速；托管服务则比较可选接口的请求与排队表现。保持原有可播放样音和配置作对照。更多线程未必更快，模型参数更多也不保证更自然。

## 控制比较条件与验收

使用同一份目标讲稿和相同的声音目标作对照；采用参考录音或文字时保持一致并保存校验值。按实际可控条件记录模型或服务版本、采样设置、资源与并行负载；本地后端还可记录量化、线程数和优先级等。参数名相同不保证两个引擎的采样算法相同。

同一实现比较 CPU/GPU 时，尽量保持权重和参数一致；跨实现或跨量化比较时，报告整个配置组合的效果，不把全部收益归因于 GPU 或线程数。输出时长不同时，既报告端到端墙钟时间，也报告每秒有效音频需要的墙钟时间；先检查内容完整，避免把漏句、截尾或提前结束当作提速。

变更实现、精度、量化或参考方式后，按 [录播主流程](recorded-talk.md) 重新核对数字、单位、术语、否定和句尾，并让用户判断口音与自然度。ASR 中的 `fourteen`/`forty` 等混淆先记录为疑点；识别正确不代表口音相似，识别不同也不直接证明实际发音错误。

需要在本地转换模型时，先核对内存与磁盘余量。若转换器把所有 F32 张量保留在内存，可使用其磁盘临时存储选项；临时目录应位于容量足够的真实磁盘，先确认默认临时目录是否为内存文件系统。依赖或头文件可放在独立任务目录，不覆盖仍在工作的后端。

对采用参考语音的方案，仅缓存音色向量不等于保存完整参考条件。性能比较应保持用户选定的声音与表达目标，不能静默改用其他参考方式或预置声音来制造提速。

## 估算整片耗时

先区分所选方案的一次性准备成本与每段开销；例如本地模型下载、编译、转换和首次参考编码，或远程服务的上传、排队及调用耗时。用复用参考后的短样音或代表性整页实测，不将首次运行总耗时直接按音频长度放大。

在当前生成方式和负载相近时，可用以下预算模型：

```text
配音耗时 ≈ 尚未完成的一次性开销
          + 页面或段落数 × 每段固定开销
          + 目标音频时长 × 稳定生成阶段的墙钟/音频时长
整片制作耗时 ≈ 配音耗时 + 内容回查 + 字幕对齐 + 视频编码
```

固定开销可包含模型加载和参考/文本预填充；稳定阶段使用真实墙钟区间，包含当时同步发生的声码器处理，避免重复计算重叠阶段。长页面的上下文、停顿、返工与最终音频时长会改变结果，应给出合理区间，并说明是否计入人工试听。短样音外推不能表述为已完成整片实测。

## 可选实现示例：Qwen3-TTS 后端接口

以下仅用于已经选用对应后端的环境，不限定其他语音工具或服务。模型格式、参考缓存和命令参数按实际接口核对，不假定不同实现可互换。

- [Qwen3-TTS C 实现](https://github.com/gabriele-mastrapasqua/qwen3-tts)：常用 `qwen_tts -d ... --load-voice ...`，音色条件可保存为 `.bin` 或 `.qvoice`。本技能的 [配置入口](tts-configuration.md) 封装这一接口。
- [qwentts.cpp](https://github.com/ServeurpersoCom/qwentts.cpp)：GGML 实现，可分别选择 CPU、Vulkan 等设备；使用独立的 Talker 和 Codec GGUF。完整参考条件可预编码为 `.spk` 和 `.rvq`，并配套参考文字。不能直接把 C 实现的 `.qvoice` 当成这些文件，也不能直接套用其配置参数。

在后端实际支持且驱动可用时，可按当前帮助尝试以下形式。这里的文件名都是占位资源名；程序路径与设备名称按本机发现结果填写。

```text
qwen-codec --model codec.gguf --talker talker.gguf --device Vulkan0 -i reference.wav
qwen-tts --model talker.gguf --codec codec.gguf --device Vulkan0 --ref-spk reference.spk --ref-rvq reference.rvq --ref-text reference.txt --lang English -o sample.wav
```

第二条命令的目标讲稿从标准输入传入；Python 可用参数数组和 `subprocess.run(..., input=text, text=True)`，不拼接带讲稿正文的 shell 命令。Windows 下使用相应可执行程序和本机设备名。不同后端的 token、帧和时长上限可能不同，先核对帮助，完整页面不要照抄短样音的上限。
